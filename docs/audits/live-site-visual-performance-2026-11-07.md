# Production screenshots and Lighthouse audit

Date: 2026-11-07. Source: `https://www.afromericaent.com/`. This documentation describes a **read-only browser audit** against the live site, not a locally reconstructed page.

## Verified project context

Next.js 16 / React 19 / Supabase / Paystack / Resend; dynamic public events and artist pages. Default branch is unchanged; capture automation lives only in `audit/visual-performance-2026-11-07`.

## How the audit runs

Visit **Actions > Live site visual + Lighthouse audit**, or inspect the run triggered by the push to the audit branch. Download `production-visual-performance-audit` from the run's Artifacts section. The ZIP contains `site-captures` and `lighthouse` subfolders.

- Desktop captures: 1440×900 viewport at 2× device pixel ratio; full-page capture at CSS pixel resolution.
- Mobile captures: 390×844 viewport at 2× device pixel ratio; full-page capture at CSS pixel resolution.
- Routes: `home` (/), `events` (/events), `artists` (/artists), `about` (/about), `contact` (/contact).
- Pages are read from production and screenshots are not redrawn or substituted with fictional UI. The audit records HTTP status, document title, scroll height, potential horizontal overflow, and page errors.
- A curated `*-portfolio-composite.png` frame is generated from the actual browser captures, preserving originals. This is a marketing presentation, not performance or correctness evidence.
- Lighthouse creates HTML/JSON reports per route and device, with categories Performance, Accessibility, Best Practices and SEO; numerical LCP, FCP, CLS, TBT and Speed Index. See `lighthouse/summary.json`.

## Important interpretation

Scores are *pending until the workflow succeeds*; never invent or infer them from repo dependencies, static source, or a mockup. Lighthouse lab simulations are not field Core Web Vitals, and TBT is **not** INP. To verify p75 real-user Core Web Vitals, use Chrome UX Report, PageSpeed Insights field data (if traffic sufficient), or approved RUM. Good field thresholds: LCP <= 2.5 s, INP <= 200 ms, CLS <= 0.1. Source: https://web.dev/articles/vitals

## Presentation workflow

Keep originals, inspect for actual content/load states, select the most representative sections, and use clean neutral framing with a restrained shadow and spacing. The composite generated by the workflow is a first automated review asset: manually approve crops, content, and visual balance before portfolio publication. Never claim the screens are official reproductions of another brand. Mask sensitive information if any appears.
